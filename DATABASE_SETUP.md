# Database Setup Guide

## Prerequisites

- PostgreSQL 12 or higher installed
- Python 3.8+ with pip

## Quick Start

### 1. Install PostgreSQL

**Ubuntu/Debian:**
```bash
sudo apt-get update
sudo apt-get install postgresql postgresql-contrib
```

**macOS (using Homebrew):**
```bash
brew install postgresql@14
brew services start postgresql@14
```

**Windows:**
Download and install from [PostgreSQL.org](https://www.postgresql.org/download/windows/)

### 2. Create Database and User

Connect to PostgreSQL:
```bash
sudo -u postgres psql
```

Create database and user:
```sql
CREATE USER supplychain WITH PASSWORD 'supplychain';
CREATE DATABASE supply_chain_db OWNER supplychain;
CREATE DATABASE supply_chain_test_db OWNER supplychain;
GRANT ALL PRIVILEGES ON DATABASE supply_chain_db TO supplychain;
GRANT ALL PRIVILEGES ON DATABASE supply_chain_test_db TO supplychain;
\q
```

### 3. Configure Environment

Copy the example environment file:
```bash
cp .env.example .env
```

Edit `.env` and update the database URL if needed:
```
DATABASE_URL=postgresql://supplychain:supplychain@localhost:5432/supply_chain_db
```

### 4. Install Python Dependencies

```bash
pip install -r requirements.txt
```

### 5. Run Database Migrations

Initialize the database schema:
```bash
# Create initial migration (only needed once, already done)
alembic revision --autogenerate -m "Initial schema"

# Apply migrations
alembic upgrade head
```

## Database Schema

### Tables

#### **locations**
- Stores geographic locations for suppliers, routes, and disruptions
- Fields: id, country, region, city, latitude, longitude, timestamps
- Indexes: coords, country_region

#### **suppliers**
- Supplier entities with reliability and capacity information
- Fields: id, name, location_id, status, reliability_score, lead_time_days, capacity, products, risk_factors
- Relationships: Many-to-One with locations
- Indexes: status, reliability_score

#### **routes**
- Transportation routes between locations
- Fields: id, origin_id, destination_id, transport_mode, distance_km, avg_duration_hours, cost_per_unit, reliability_score, status
- Relationships: Many-to-One with locations (origin and destination)
- Indexes: origin_dest, status

#### **disruptions**
- Supply chain disruption events
- Fields: id, type, severity, location_id, description, start_time, end_time, affected_suppliers, affected_routes, predicted_impact_score, source, is_active
- Relationships: Many-to-One with locations, One-to-Many with alerts and response_plans
- Indexes: type_severity, active, time_range

#### **alerts**
- Crisis alerts generated by the system
- Fields: id, timestamp, disruption_id, severity, title, message, recommended_actions, affected_entities, estimated_financial_impact, acknowledged, acknowledged_at, acknowledged_by
- Relationships: Many-to-One with disruptions
- Indexes: severity_time, acknowledged

#### **response_plans**
- Automated response plans for disruptions
- Fields: id, disruption_id, created_at, priority, alternative_suppliers, alternative_routes, inventory_adjustments, estimated_cost, estimated_time_to_resolve, confidence_score, status, approved_at, approved_by, implemented_at
- Relationships: Many-to-One with disruptions
- Indexes: priority, status

#### **events**
- Raw events from intelligence sources
- Fields: id, event_id, source, event_type, title, description, url, published_at, location_*, latitude, longitude, severity_score, confidence_score, raw_data, processed
- Indexes: source_time, processed, location

## Database Operations

### Manual Database Initialization

If you prefer to initialize without Alembic:

```python
from src.database.engine import init_db
init_db()
```

### Using with Context Manager

```python
from src.database import get_db_context
from src.database.repositories import SupplierRepository

with get_db_context() as db:
    suppliers = SupplierRepository.get_all(db)
    print(f"Found {len(suppliers)} suppliers")
```

### Using with Dependency Injection (FastAPI)

```python
from fastapi import Depends, FastAPI
from sqlalchemy.orm import Session
from src.database import get_db
from src.database.repositories import SupplierRepository

app = FastAPI()

@app.get("/suppliers")
def get_suppliers(db: Session = Depends(get_db)):
    suppliers = SupplierRepository.get_all(db)
    return {"suppliers": [s.to_dict() for s in suppliers]}
```


### Apply migrations
```bash
alembic upgrade head
```

### Rollback one migration
```bash
alembic downgrade -1
```

### View migration history
```bash
alembic history
```

### Check current revision
```bash
alembic current
```

## Backup and Restore

### Backup
```bash
pg_dump -U supplychain -d supply_chain_db -F c -f backup_$(date +%Y%m%d).dump
```

### Restore
```bash
pg_restore -U supplychain -d supply_chain_db -c backup_20231115.dump
```

## Performance Tuning

### Connection Pooling

The system uses SQLAlchemy's connection pooling with these defaults:
- Pool size: 5
- Max overflow: 10
- Pool timeout: 30s
- Pool recycle: 3600s

Adjust in `.env` if needed:
```
DB_POOL_SIZE=10
DB_MAX_OVERFLOW=20
```

### Query Optimization

All tables have indexes on frequently queried columns:
- Foreign keys
- Status fields
- Timestamp fields
- Coordinates

## Troubleshooting

### Connection Issues

**Problem:** `OperationalError: could not connect to server`

**Solution:**
1. Check PostgreSQL is running: `sudo systemctl status postgresql`
2. Verify connection string in `.env`
3. Check PostgreSQL is accepting connections: `pg_isready`

### Permission Issues

**Problem:** `OperationalError: permission denied`

**Solution:**
```sql
GRANT ALL PRIVILEGES ON DATABASE supply_chain_db TO supplychain;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO supplychain;
GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO supplychain;
```

### Migration Conflicts

**Problem:** `alembic.util.exc.CommandError: Target database is not up to date`

**Solution:**
```bash
# Check current state
alembic current

# Force to head (use with caution in production)
alembic stamp head

# Or rollback and reapply
alembic downgrade base
alembic upgrade head
```

## Security Best Practices

1. **Never commit `.env` files** - Use `.env.example` as template
2. **Use strong passwords** - Change default password in production
3. **Limit database access** - Use firewall rules and PostgreSQL pg_hba.conf
4. **Enable SSL/TLS** - For production database connections
5. **Regular backups** - Automate daily backups
6. **Monitor connections** - Set up alerts for connection pool exhaustion

## Production Deployment

### Using Managed PostgreSQL (Recommended)

- **AWS RDS**: [https://aws.amazon.com/rds/postgresql/](https://aws.amazon.com/rds/postgresql/)
- **Google Cloud SQL**: [https://cloud.google.com/sql/postgresql](https://cloud.google.com/sql/postgresql)
- **Azure Database**: [https://azure.microsoft.com/en-us/products/postgresql](https://azure.microsoft.com/en-us/products/postgresql)

Update `DATABASE_URL` in production environment:
```
DATABASE_URL=postgresql://user:password@production-host:5432/dbname?sslmode=require
```

### Migration in Production

```bash
# Always backup first!
pg_dump -U user -d dbname -F c -f pre_migration_backup.dump

# Test migration on staging first
alembic upgrade head --dry-run

# Apply migration
alembic upgrade head
```
